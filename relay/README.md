# コトダマ中継サーバー（APIキーなしで、PCのClaudeを使う）

GitHub Pages のコトダマ（https://tanakatakeshi811-spec.github.io/kotodama/）から、**このPCにログイン済みの Claude Code** を呼ぶための小さなサーバーです。APIキーは要りません。使った分は、Claude の使用量に数えられます。

```
コトダマ（ブラウザ） → 中継サーバー（このPC） → claude -p（ログイン済みClaude Code） → 答えをそのまま返す
                ↑ 同じPCなら http://127.0.0.1:8787
                ↑ スマホなど外からは Cloudflare Tunnel（https://〜.trycloudflare.com）経由 ＋ 合言葉
```

## A. このPCだけで使う（かんたん）

1. 一度だけ：Node.js（18以上）と Claude Code を入れて、`claude` でログインしておく
2. `start-relay.bat` をダブルクリック（黒い窓が開く。**開いている間だけ**使える）
3. コトダマを開く。つながると「AIにつながっていません」の案内が消える（先に開いていたら、設定 → 接続 →「接続を試す」）

## B. スマホなど外からも使う（Cloudflare Tunnel ＋ 合言葉）

1. `relay/passphrase.txt` に**合言葉を1行だけ**書く（このファイルはGitに載せない設定。公開リポジトリには置かないこと）
2. `cloudflared.exe`（Cloudflare公式）を `server.mjs` と同じフォルダに置く（無ければ PATH の `cloudflared` を探す）
3. `start-relay-tunnel.bat` をダブルクリック。黒い窓に「外からつながる住所」と、スマホで開くリンクが出る
4. スマホでそのリンクを開く → 住所が自動で入る。設定 → 接続 で**合言葉を入れて「接続を試す」**（以後はその端末に覚えさせる）
5. 終わったら黒い窓を閉じる。トンネルも一緒に止まる

- 住所は起動のたびに変わる（無料の一時トンネルのため）。起動するたびに、表示されたリンクをスマホで開き直す
- 合言葉が未設定のときは、外には公開しない

## 検索とリサーチ（＋ボタンのメニュー）

- **検索をかける**：オンにすると、送るたびに Claude Code の検索（WebSearch）とページ取得（WebFetch）で調べて、その結果もふまえて答える。調べている内容は回答の上の折りたたみに出る
- **リサーチモード**：テーマ全体を、**決めた時間（最短 1〜600 分。既定30分）以上**、ウェブで調べ続けてから答える。数分ごとの「回」に分けて調査ノートを積み、最短時間を過ぎたらノートをもとに最終回答を書く（出典URLつき）
  - 回ごとの方針：1回目は全体像と論点づくり → 深掘り → 反対意見・最新・数値の裏取り → 抜け漏れ点検
  - 画面を閉じても、トンネルが切れても、中継サーバーが動いている限り調査は続く（ブラウザは数秒おきに経過を見に来るだけ）
  - チャットの「止める」で調査を打ち切る。使用制限に達したときは、そこまでのノートで答える
  - **使用量をたくさん使う**（調査1回ごとに何度も検索・読み込みをするため）。時間を長くするほど増える
  - 同時に動かせるリサーチは1つだけ。中継サーバーを再起動すると、実行中のリサーチは消える

## 画面を閉じても返信は続く（あとで受け取り）

チャットを送ると、中継サーバー（PC）が返信を「ジョブ」として最後まで作り続ける。送ったあとにブラウザや画面を閉じても、スマホがスリープしても、通信が切れても、**PCの中継サーバーが動いている限り**返信は作られる。コトダマを次に開いたとき（中継サーバーにつながったとき）に、続きと結果が自動で会話に入り、「返信が届きました」と出る。リサーチモードも同じ。

- 終わった返信は24時間、`jobs-store.json`（このフォルダ。Gitには載せない）にも残るので、中継サーバーを再起動しても、終わっていた分は受け取れる。作っている途中で再起動した分は失われる（「返信が消えました」と出る）
- 受け取りの記録（どのチャットのどの返信か）は、ブラウザの `localStorage`（`kd:pendingJobs`）に持つ。別のブラウザ・端末には引き継がない
- 対象は、中継サーバー経由の通常チャットとリサーチ。LIVE、APIキー、Claudeアプリの中は対象外
- 「止める」を押すと、PC側のジョブも止まる

## 声（VOICEVOX）— スマホからも

中継サーバーは、このPCの VOICEVOX（`%LOCALAPPDATA%\Programs\VOICEVOX\vv-engine\run.exe`）を自動で起動して、`/vv/speak`（文字→声）と `/vv/speakers` を中継する。コトダマの設定 → 声・LIVE → 使うサービス「おまかせ」（初期値）だと、次の声で話す：

| いまのモード | 声 |
|---|---|
| 天和（天使モード） | 猫使ビィ |
| シアン | 離途 |
| ドット絵モード | 満別花丸（ボーイ） |
| ふだん（なにも設定していない） | 猫使アル |

文ごとに「様子」を見て声色も切り替える（まじめ・注意・謝罪→シリアス／おちつき、うれしい→うきうき、つかれた→へろへろ など。キャラが持っていない声色はノーマル）。設定の「文の様子で声色を変える」でオフにできる。

- VOICEVOX が見つからないときは、端末の声で読み上げる（30秒は再試行しない）
- 起動直後に、よく使う声（8種類）を先に読み込む（約30秒）。GPU（`VOICEVOX_GPU=1`）は、声ごとの最初の読み込みが40秒以上かかるので、標準ではCPUを使う
- 合成はPCの性能しだいで、1文あたり2〜5秒かかる。LIVEでは最初の一言を読点（、）まででいったん区切って、早く声を出し始める

## 返事を速くする工夫

- 思考（thinking）は、effort が「低・中」のときは切る（最初の文字まで約2秒短縮）
- よく使う設定（Haiku／Sonnet・低）の分は、起動済みで入力待ちの Claude Code を1つ用意しておき、リクエストが来たら使う（使ったらすぐ次を用意）。最初の文字まで、Haikuで約0.7〜2秒、Sonnetで約1.1〜2.4秒
- サーバーは10秒ごとに生存信号を送り、ブラウザは75秒なにも届かなければ切れたとみなして打ち切る（待ちっぱなしにならない）

## 守っていること

- 待ち受けは `127.0.0.1` だけ。外からの要求はトンネル経由でしか届かない
- 許可する画面は `https://tanakatakeshi811-spec.github.io` と `localhost` だけ。ほかのサイトからの呼び出しは断る（環境変数 `ORIGINS` で変えられる）
- トンネル経由の要求には合言葉が必須。5回まちがえた相手は15分ロック、全体で1時間に30回まちがえると止まる
- Claude Code に渡す道具は、通常は「なし」。検索・リサーチのときだけ WebSearch / WebFetch の2つを許可する（ファイル操作やコマンド実行はしない）。設定も読ませない
- 同時に処理するのは3件まで

## できないこと・注意

- PCが起動していて、黒い窓が開いている間だけ使える
- 画像は1回に4枚まで（LIVEのカメラ映像も、写真の添付も送れる）
- 合言葉は短い数字だと推測されやすいので、できれば長めに。住所（ランダムな長い名前）を知られなければ、まず届かない
- Chrome で「ローカルネットワークへのアクセス」を聞かれたら許可する。Safari は https のページから http のローカルへの通信を止めることがある（外から使うトンネル方式なら https なので問題なし）
